# Прокси API через Cloudflare Worker

Нужен, потому что провайдеры сбрасывают соединение с `*.render.com` (`net::ERR_CONNECTION_RESET`),
и пользователи без туннеля получают пустой каталог. `workers.dev` при этом доступен.

## Что делает воркер

`cloudflare/api-proxy.worker.js` — прозрачный прокси: сохраняет путь, метод, заголовки и тело запроса,
пересылает всё на Render и отдаёт ответ как есть, включая CORS-заголовки сервера.
Секретов внутри нет, адрес origin захардкожен на публичный API.

## Настройка (без установки чего-либо на компьютер)

1. Cloudflare dashboard → **Compute & Workers → Workers → Create** → **Hello World** → дать имя, например `b2b-market-api`.
2. В открывшемся редакторе заменить весь код содержимым `cloudflare/api-proxy.worker.js` → **Deploy**.
3. Проверить в браузере: `https://<имя>.workers.dev/api/health` — должен вернуться тот же JSON, что и с Render.
4. GitHub → **Settings → Secrets and variables → Actions → New repository variable**:
   - Name: `API_BASE_URL`
   - Value: `https://<имя>.workers.dev/api`
5. Перезапустить деплой Pages: GitHub → Actions → Deploy to GitHub Pages → Run workflow (ветка `develop`).

После этого сайт обращается к воркеру, а воркер — к Render. Откат — удалить переменную `API_BASE_URL`:
сборка снова возьмёт адрес Render напрямую.

Где взять точный адрес воркера: Cloudflare dashboard → Workers & Pages → имя воркера → вверху указан
`https://<имя>.<что-то>.workers.dev`. Копировать нужно его целиком: `https://<имя>.workers.dev` без
аккаунтной части не существует, и браузер получит `ERR_NAME_NOT_RESOLVED`. Проверить можно так:
`dig +short <адрес>` должен вернуть хотя бы один IP.

В этом проекте воркер опубликован как `https://b2b-market-api.cosmocats08.workers.dev`, и этот адрес
стоит в репозиторной переменной `API_BASE_URL` (GitHub → Settings → Secrets and variables → Actions → Variables).

## Запасной маршрут

Клиент знает оба адреса (`shared/apiEndpoints.js`) и выбирает тот, который отвечает в этой сети:

- Рабочим считается маршрут, ответивший на запрос или на health-опрос, — только он сохраняется
  в `localStorage` этого браузера. Переключение «наугад» не запоминается, поэтому неудачный выбор
  не может обезглавить сайт насовсем.
- Заблокированный провайдером адрес не отбивается ошибкой сети, а висит до таймаута. Поэтому
  health-опрос при проблемах с соединением перебирает оба маршрута, а не только текущий: живой
  адрес становится рабочим в течение нескольких секунд.
- Холодный старт сервера маршрут не меняет: запросы ждут пробуждения через общий health-опрос.

## Что нужно знать

- Бесплатный лимит Workers — 100 000 запросов в сутки; health-опросы и повторы укладываются с запасом.
- Браузерский `Origin` (`https://coffeecat45.github.io`) пересылается как есть, поэтому allowlist CORS на Render
  менять не нужно. `connect-src` собирается из `VITE_API_BASE_URL` при сборке, а прямой адрес API добавляется
  всегда — ради запасного маршрута.
- Холодный старт Render может длиться около минуты. Если воркер не дождётся ответа, браузер получит
  ошибку сети; клиент в этом случае ждёт пробуждения БД одним общим health-опросом и повторяет запрос.
  Чтобы убрать паузу вовсе, можно пинговать Render по расписанию — это отдельное решение.
- воркер не кэширует ответы и не меняет их, поэтому поведение API совпадает с прямым обращением.
